# 配单 / 选料方法论（Methodology）

> **这份文档回答什么**：拿到「一句话需求」或「一张 BOM 表」之后，agent 应该**按什么顺序做什么判断、每步用哪条命令、什么情况必须停下来问人**。
>
> **这份文档不回答什么**：接口字段细节（→ `lcsc-api.md`）、单条指标的判定算法（→ `spec-check.md`）、渠道性格（→ `channels.md`）、按意图找料的入口（→ `pick-intent.md`）。本文只做**编排**，把上面几份串成一条可执行的链。
>
> **知识库**：`data/knowledge/*.yaml` 是本文所有阈值/清单的机读版。本文给人读，YAML 给脚本读，**两者改一处必须同步另一处**。

## 0 三条第一性原理

### 0.1 「刚好够用」是目标函数，不是「最好」

选型不是选性能最强的，是**选满足需求的最便宜那个**。商业量产的技艺是知道能把设计糙化到什么程度还能刚好工作。
**但「糙化」有硬边界**：降额、安规、认证、定时基准不可糙化。边界 = `data/knowledge/risk-checklist.yaml` 里 `severity: blocker` 的条目。

### 0.2 「绝对最大值」≠「安全工作值」

数据手册的 `Vds = 30V` / `Id = 5A` 是**器件不立即损坏的极限**，不是可用工作点。24V 系统的**瞬态**经常到 40V+；`Vgs = 2.5V` 下的 `Rds(on)` 可能是 `Vgs = 10V` 的 **2.8 倍**（AO3400A：48mΩ vs 17mΩ）。
**所以任何参数都必须带测试条件比较**，不能只比数字。判据见 `spec-check.md` §2。

### 0.3 可解释 > 准确

配单错了要**报废整板**。所以每一行判定都必须能说清「查了什么、没查什么、为什么存疑」。
**宁可给 `?`，不给错的 `✔`。** 五档标记的含义见 §6.3。

## 1 全景：D0–D9 十步决策链

| 步 | 名称 | 一句话目标 | 主命令 | 硬门 |
|---|---|---|---|---|
| D0 | 入口分类 | 判断用户给的是「一句话需求」还是「BOM 表」 | — | 都不是 → 问 |
| D1 | 需求澄清 | 把模糊描述补成可检索的参数集 | `pick.py cats` | 缺关键参数 → 问 |
| D2 | 品类与参数确定 | 意图 → family → 必填参数 | `pick.py resolve` | family 未收录 → 问 |
| D3 | 候选生成 | 拿到 5–20 个候选 | `pick.py pick` / `lcsc.py search` | 0 候选 → 降级 |
| D4 | 指标核对 | 逐条比对，出五档判定 | `spec.py` / `lcsc.py compare` | 任一 `✘` → 停 |
| D5 | 成本与渠道 | 算出「在哪买、买多少、多少钱」 | `bom.py` / `taobao.py search` | 整单 ≥500 元 → 询盘 |
| D6 | 风险复核 | 过一遍风险清单 | 见 `risk-checklist.yaml` | 任一 blocker → 停 |
| D7 | 替代料裁决 | 有替代就裁决，没有就承认 | `lcsc.py alternate` | 高风险类 → 原型号 |
| D8 | 下单与留痕 | 出报价单 + 落盘原始数据 | `bom.py --md --json` | 红色行 → 停 |
| D9 | 到货验收 | 抽检 + 归档 | — | 外观异常 → 停 |

**这张表的用法**：不要跳步。跳 D1 会导致检不到料，跳 D4 会导致买回来不能用，跳 D6 会导致批量翻车。**每一步的输出是下一步的输入，缺一步整条链就断了。**

## 2 D0 入口分类

### 输入

用户的一句话。可能是：
- **A 类「一句话需求」**：`"3.3V 1A 的 LDO"`、`"30V 5A 的 N 沟道 MOS"`、`"10uF 25V 0805 电容"`
- **B 类「BOM 表」**：CSV / Excel / 粘贴的表格，含位号、型号、封装、数量
- **C 类「型号直查」**：`"C8734 多少钱"`、`"STM32F103C8T6 有没有货"`
- **D 类「都不是」**：`"帮我看看这个电路行不行"`、`"这个料还能买吗"`（没有型号也没有参数）

### 动作

| 类别 | 走哪条链 | 首个命令 |
|---|---|---|
| A 类 | D1 → D9（**从需求澄清开始**） | `python scripts/pick.py cats` |
| B 类 | D0.5 格式体检 → D4 → D9（**跳过 D1–D3**） | `python scripts/bom.py <bom> --columns` |
| C 类 | D4 → D5（**直接核对 + 报价**） | `python scripts/lcsc.py detail <code>` |
| D 类 | **停下来问人** | — |

### 判据

- A 类：需求里**必须能抽出至少一个定量参数**（电压/电流/容值/阻值/频率/封装之一）。抽不出 → 走 D 类。
- B 类：表格**必须有序号列 + 型号列 + 数量列**。缺型号但有参数 → 逐行降级成 A 类。
- C 类：型号必须是**可检索的完整型号**，不是系列名（`"LM358"` 可以，`"运放"` 不行）。

### 常见错误

| 错 | 后果 | 修正 |
|---|---|---|
| 把 A 类当 C 类硬查 | 检索不到，误报「无货」 | 先 `pick.py cats` 看 family |
| 把 B 类当 A 类逐行问 | 用户被问 20 遍 | 先 `bom.py --columns` 看列名 |
| D 类硬编一个参数 | 选错料，整板报废 | **必须问** |

## 3 D1 需求澄清

### 输入

A 类需求的一句话描述。

### 动作

**1. 先看系统支持哪些品类**

```powershell
python scripts/pick.py cats
```

输出 25 个 family（`resistor` / `mlcc` / `ldo` / `mosfet` / `mcu` / …），每个带 `label_cn`。

**2. 确认需求落在哪个 family**

```powershell
python scripts/pick.py resolve "3.3V 1A 的 LDO"
```

`resolve` 只做「关键词 → family 映射」，**不检索**。目的是让 agent 知道自己理解得对不对，错得早比错得晚好。

**3. 补齐该 family 的必填参数**

每个 family 的 `required_to_specify`（见 `data/spec-rules.yaml`）必须逐项有值。缺项走 §12 的「必须停下来问人」。

### 判据

- `resolve` 返回 **1 个 family** → 继续
- 返回 **多个 family** → 用「最具体的那个」，并在输出里注明「也可能属于 X」
- 返回 **0 个 family** → 停下来问，或加 `--allow-unknown` 走自由检索（**结果需人工确认**）

### 常见错误

| 错 | 后果 | 修正 |
|---|---|---|
| 不跑 `resolve` 直接搜 | 用错 family 的参数表核对 | 先 resolve |
| 缺参数时自己假设 | 选出来的料不满足真实工况 | 列缺失参数问用户 |
| 把「LDO」和「DCDC」混为一谈 | 效率/发热判断反了 | LDO 压差×电流=纯发热；DCDC 看效率 |

## 4 D2 品类与参数确定

### 输入

D1 产出的 family + 已确认参数。

### 动作

**1. 读该 family 的判据表**

```powershell
# 人读
Get-Content skills\bom-sourcing\data\spec-rules.yaml | Select-String -Pattern "^\s{2}ldo:"
```

**2. 明确「关键参数」与「次要参数」**

`spec-rules.yaml` 的 `critical:` 是**必须核对**的，`conditional_critical:` 是**满足条件才核对**的。
例：`resistor.critical = [resistance, package, power_rating, tolerance]`；`conditional_critical` 里有一条「用于分压/基准/滤波网络」→ 收紧 `tempco <= 100ppm/℃`。

**3. 判断是否触发条件项**

| 触发条件 | 收紧项 | 出处 |
|---|---|---|
| 分压 / 基准 / 滤波网络 | 电阻 `tempco <= 100ppm/℃`，`tolerance <= 0.5%` | `spec-rules.yaml` |
| 电源轨上的 Class II MLCC | **额定电压 ≥ 2× 工作电压** | `industry-norms.yaml` → `hidden_stress.mlcc_dc_bias` |
| 高温环境（柜内 60℃+） | 全部降额按「最坏工况」重算 | §6.2 |
| 安规 / 隔离 / 保险丝 | **不可替代**，一律原型号 | `risk-checklist.yaml` |

### 判据

- 所有 `critical[].key` 都有值 → 继续 D3
- 有 `conditional_critical` 被触发但缺值 → **必须回头问**

### 常见错误

| 错 | 后果 | 修正 |
|---|---|---|
| 只看 `critical` 不看 `conditional_critical` | 精密分压用了普通电阻，温漂超标 | 逐条对 `when` |
| 用标称容值设计 Class II 电容 | 实际有效容值只有 15%（见 §6.4） | 按 2× 电压选 |
| 忽略封装 | 焊盘对不上 | 封装进 `critical` |

## 5 D3 候选生成

### 输入

family + 参数集 + 数量。

### 动作

**1. 首选：`pick.py pick`（意图 → 品类 → 候选，一条命令走完）**

```powershell
python scripts/pick.py pick "3.3V 1A LDO" --package SOT-23-5 --qty 100 --sort sales --limit 10
```

**2. 次选：`lcsc.py search`（已知关键词，直接搜）**

```powershell
python scripts/lcsc.py search "AMS1117-3.3" --sort price_asc --limit 20 --qty 100 --show-params
```

**3. 需要外部渠道交叉时：`taobao.py` / `distributor.py`**

```powershell
python scripts/taobao.py search "STM32F103C8T6" --site taobao --sort sales --limit 20
python scripts/distributor.py search "TPS259472ARPWR" --site both --limit 5
```

### 判据

- 候选数 **≥5** → 继续 D4
- 候选数 **1–4** → 继续，但**必须在输出里注明「候选稀缺，议价空间小」**
- 候选数 **0** → 依次尝试：①去掉 `--package` ②`--include-out-of-stock` ③放宽精度/耐压 ④`taobao.py` 反向找同参数 ⑤**报「无货」，不要编造型号**

### 常见错误

| 错 | 后果 | 修正 |
|---|---|---|
| 用销量排序当主判据 | 选到开发板/套件 | 销量只做 tie-breaker（`market-probe.md` §4） |
| 0 候选就报「停产」 | 其实只是参数太严 | 逐级放宽再报 |
| 忘记 `--qty` | 拿到的是 1 只的价 | 报价必须带数量 |

## 6 D4 指标核对

> 本步是整条链**最不能省**的一步。方法细节见 `spec-check.md`，这里只讲编排。

### 6.1 动作

**1. 取候选的完整参数**

```powershell
python scripts/lcsc.py detail C8734
```

**2. 多候选横向对比**

```powershell
python scripts/lcsc.py compare C8734 C1234 C5678 --qty 100
```

**3. 单条规格自检（不联网）**

```powershell
python scripts/spec.py          # 跑内置 5 个样例自测
```

### 6.2 降额核对（硬阈值）

> 出处：`data/knowledge/industry-norms.yaml` → `derating:`（商业档 / 高可靠档两档并列）

| 器件 | 商业档（默认） | 高可靠档 | 备注 |
|---|---|---|---|
| MLCC Class II 电压 | ≤80% 额定 | ≤50–60% | IPC-9592B 允许 90%，本仓取 80% |
| MLCC Class I (C0G) 电压 | ≤80–90% | ≤60% | |
| **钽电容（MnO2）电压** | **≤50%（强制）** | ≤50% | 失效模式 = 热失控 + 短路 |
| 铝电解 电压 / 纹波 | ≤80% / ≤80% | ≤70–80% / ≤70% | |
| 电阻 功率 | ≤50–60% | ≤50% | |
| MOSFET `Id` / `Vds` / `Tj` | ≤75–80% / ≤80% / ≤80% | ≤60–70% / ≤75% / ≤70% | |
| 二极管 `PIV`/`VRRM` | ≤70–80% | ≤50–60% | |
| IC 供电 / `Tj` | ≤90% / ≤80% | ≤80% / `Tj`<100℃ | |
| 电感/变压器 电流 | ≤80% | ≤70% | |
| 继电器 触点电流 | ≤75% | ≤60–70% | |
| 保险丝 | ≤75%@25℃ | ≤70% | **慢断每高于 25℃ 再降 0.5%/℃** |
| 连接器 每针 | ≤80% | ≤70% | 相邻针载流要**成组**降额 |

**通用余量**：1.2–1.5×（`cn-knowledge.md` A3）。

> **两套口径别搞混**：上表是**百分比**（给人读，出处 IPC-9592B）；`data/spec-rules.yaml` 的 `globals.voltage_derating` 是**倍数**（给脚本吃）。换算 `percent = 1 / multiplier`。
> **MLCC 有两条独立约束，取更严的**：①电压降额（热/击穿）1.25×；②直流偏压（有效容值）**2.0×**。**电源轨上按 2.0×**。两者不一致时以 `spec-rules.yaml` 为准，并回改 `industry-norms.yaml`。

### 6.3 五档判定

| 标记 | 含义 | 处理 |
|---|---|---|
| `✔` | 完全匹配 | 可直接下单 |
| `≈` | 等效（阻值/容值相对误差 ≤2%） | 可直接下单 |
| `?` | 待确认（参数缺失或条件不全） | **必须人工确认** |
| `!` | 警告（非关键项超标 / 降额不足） | 需说明理由才能用 |
| `✘` | 不匹配 | **淘汰** |

**规则**：
- 任一 `✘` → **整行不可用**，回 D3 重选
- 任一 `?` → 输出里必须写清**缺什么**
- **`spec.verify()` 在 MLCC 耐压 < 需求×1.25 或钽 < 2× 时只给 `i` 提示，不淘汰候选** —— 这是设计意图，不是 bug

### 6.4 隐性应力（最容易漏）

| 隐性应力 | 判据 | 后果 |
|---|---|---|
| **MLCC 直流偏压容值损失** | 电源轨上 Class II MLCC **额定电压 ≥ 2× 工作电压** | 0402 10µF/6.3V X5R 在 5V 下只剩 **~1.5µF（−85%）** |
| MOSFET 漏极振铃 | 瞬态可比稳态高 **50%+** | 稳态 24V 要按 36V 选 `Vds` |
| 连接器相邻针载流 | 成组降额，不是逐针算 | 多针同时载流会超温 |
| 海拔 | >2000m 需额外降额 | 空气绝缘强度下降 |

**真实事故（务必读）**：3000 台工业网关用 `10µF/10V X5R` 在 5V 轨（以为有 50% 余量），中东户外柜内 65–70℃ 下 **8 个月开始批量复位**，最终改 `10µF/25V X7R 0805` 并重开板，**损失 >20× 前期省下的 BOM 成本**。

### 6.5 常见错误

| 错 | 根因 | 修正 |
|---|---|---|
| 只降电压不看温度 | 降额是**温度相关**的 | 按「最坏工况」重算 |
| 用标称容值设计 | 忽略偏压/温度/老化 | 见 §6.4 |
| 拿 25℃ 的 `Id` 当可用电流 | 封装热阻 | 算 `Tj = Ta + Pd·RthJA` |
| **全面过度降额** | 更大封装 = 更易弯曲开裂 | 降额是**定值判据**，不是越大越好 |
| 把降额当散热方案 | 降额降低发热但不改善散热路径 | 该加散热就加 |
| **缺货换料后不重跑降额** | 忘了新料的参数不同 | 换料必须回到 D4 |

## 7 D5 成本与渠道

### 7.1 动作

**1. 立创报价（含阶梯价）**

```powershell
python scripts/lcsc.py price C8734 --qty 100
```

**2. 整单报价单**

```powershell
python scripts/bom.py bom.csv --qty 100 --pref price --md 报价单.md --json 报价单.json
```

**3. 外部渠道比价（按数量阈值决定要不要做）**

```powershell
python scripts/taobao.py search "STM32F103C8T6" --site taobao --sort price_asc --limit 20
python scripts/taobao.py search "STM32F103C8T6" --site 1688 --sort price_asc --limit 20
```

### 7.2 渠道选择判据

| 数量 / 金额 | 首选 | 理由 |
|---|---|---|
| 单型号 ≤10 只，或单品总价 <50 元 | **淘宝** | 无 MOQ、包邮、单价最低 |
| 单型号 10–100 只 | **淘宝比价 + 1688 询价并看** | 淘宝仍可能更便宜；1688 需确认阶梯价存在 |
| 单型号 ≥100 只，或整单 ≥500 元 | **1688 首选 + 立创做价格锚** | 起批量与对公开票才有意义；**阶梯价自动化取不到，需人工询盘** |
| 必须正品 + 要发票 + 少量 | **京东**（次选立创） | 溢价可接受 |
| MCU / 电源 / 晶振 / 连接器（任意量） | **立创优先** | 正品保障 + 参数结构化 |
| 停产 / 缺货 / 反向选型 | 淘宝销量排序找同封装同参数 → 1688 确认在产 | 反向选型靠热度不靠参数表 |

**实测价差**（`market-probe.md` §5）：STM32F103C8T6 裸片 淘宝 ¥1.02–1.45 / 1688 ¥4.00–5.15 → **小批量淘宝更便宜**。
**同规格品牌价差**：SS34 **15×** / 1N4007 **7×** / AMS1117 **5×** / AO3400A **3.2×** → **品牌是最安全的降本维度**。

### 7.3 数量与损耗

| 类别 | 损耗率 | 每款多备 |
|---|---|---|
| 常规阻容（0402 及以上） | 0.3%–0.5% | 5–10 颗 |
| 0201 / 01005 | 0.5%–1.0% | 10–20 颗 |
| **BGA / QFN / IC** | **零损耗，不允许抛料** | 0 |
| 连接器 / 异形件 | 0.5%–2.0% | — |

**口诀**：「阻容类千分之三，IC 不允许丢料」。
`bom.py` 默认按损耗模型算 `order_qty()`，`--no-spares` 关闭。

### 7.4 成本口径（必须写进报价单）

| 成本项 | 值 | 出处 |
|---|---|---|
| 器件单价 | 立创含税单价，按数量取阶梯 | `lcsc.py price` |
| **扩展库换料费** | **20 元/型号**（基础库不收） | 嘉立创口径 |
| 运费 | 按渠道 | — |
| **物料归一化成本** | `扩展库型号数 × 20 元` | 见下 |

> **归一化是最容易被忽略的降本点**：一个 40 料号的 BOM 里若有 10 个扩展库料，就是 **200 元**，小批量时经常比器件总价还大。**用 3 个阻值 vs 用 1 个，在报价单上必须有区别。**

### 7.5 常见错误

| 错 | 后果 | 修正 |
|---|---|---|
| 没算损耗 | 少买，二次下单 | 按 §7.3 |
| 忽略换料费 | 报价偏低 | 加归一化成本行 |
| 用 1688 的「1 个起批」价当批发价 | 结论反了 | 1688 价是挂牌价，量小不给折 |
| 拿淘宝的价去比立创的库存 | 错配 | **part / supplier-item 必须分开**（见 §15.1） |

## 8 D6 风险复核

### 动作

逐条过 `data/knowledge/risk-checklist.yaml`，**只关注 `severity: blocker` 与 `severity: major`**。

```powershell
python -c "import yaml;d=yaml.safe_load(open(r'skills\bom-sourcing\data\knowledge\risk-checklist.yaml',encoding='utf-8'));[print(r['id'],r['severity'],r['name']) for r in d['risks']]"
```

- 有 `severity: major` 命中 → 输出里**必须列出**，并给规避动作

### 高风险类别（不可替代）

| 类别 | 举例 | 为什么 |
|---|---|---|
| 安全 / 认证 | 安规 X/Y 电容、隔离器件、保险丝 | 认证失效 = 产品不能卖 |

## 9 D7 替代料裁决

### 动作

**1. 查立创替代料**

```powershell
python scripts/lcsc.py alternate C8734 --qty 100 --limit 10
```

底层是 `POST list.szlcsc.com/substitute/simple/list`，返回带 `simScore`（相似度分）。

**2. 对候选做 D4 的指标核对**（不能省）

### 判据

**风险三档**：

| 档 | 器件 | 验证动作 |
|---|---|---|
| **高（不建议替）** | MCU/主控、电源芯片（DCDC/LDO）、晶振、连接器 | 完整功能 + EMC / 满载 + 温升 / 实测频率 + 起振 / 插拔 + 接触电阻 |
| **中（谨慎替）** | MOSFET、运放/比较器、EEPROM/Flash | 温升 / 信号完整性 / 读写 |
| **低（可替）** | 电阻、电容、二极管、LED | 但**电容必须同介质材质**（X7R/X5R/C0G） |

**四步验证法**：①参数对比（偏差 >10% 谨慎）②功能测试（<5% 可接受）③可靠性（高低温 −20~70℃、老化 85℃×168h 或 48h、漂移 <5%）④**批量先产 10–20 片**。报告存档 ≥2 年（汽车电子 15 年+）。

### 关键警告

> **`simScore` 高 ≠ 可直接替换。** 相似度只说明「参数接近」，不说明「FFF（Form-Fit-Function）等价」。替代必须**逐项列出哪里不一样**（CTP 的 delta 认证原则）。

### 常见错误

| 错 | 后果 | 修正 |
|---|---|---|
| 用 `simScore` 直接替换 | 功能异常 | 走四步验证 |
| 换料后不重跑降额 | 隐性超标 | 回 D4 |
| 硬凑替代品 | **最危险的失败模式** | 见下 |

### 「没有替代料」是合法结论

有些老器件（如锗管 1N34）**没有真正等价的替代品**。此时正确输出是**「建议改设计」+ 成本对比（改板 vs 囤料 vs 换方案）**，而不是推荐一个勉强能用的。**编一个替代料比说「没有」危险得多。**

- 缓存 6 小时在 `%LOCALAPPDATA%\bom-sourcing\cache`，`--no-cache` 强制刷新
- **抽取结论只引用落盘数据**，不凭记忆

## 11 D9 到货验收

### 动作

1. **核对外观**（打磨翻新料七条）：打磨痕迹 / 引脚光亮 / 印字锯齿 / 日期混乱 / **边沿直角 vs r 角** / 定位孔深浅不一 / 包装差异。**丝印用稀释剂能擦掉 = 假**。
2. **核对批次**：同批次的日期码应一致，混批要警惕。
3. **抽检**：至少抽 1–2 只做通电/参数验证（高风险类全检）。
4. **归档**：把到货照片、批次号、检验结论记入项目文档。

### 判据

- 外观任一异常 → **停止使用，退货**
- 「散新料」= 拆机翻新（国产 32 位 MCU 翻新件不良率 **10%–40%**）

## 12 必须停下来问人的 12 个时刻

> **这一节是硬门。任何一条命中都必须停止自动化，把问题抛回给用户。**

| # | 时刻 | 为什么必须停 |
|---|---|---|
| 1 | 需求里**抽不出任何定量参数** | 无法检索，猜必错 |
| 2 | family 未收录且 `--allow-unknown` 结果不确定 | 参数表可能不适用 |
| 3 | `conditional_critical` 被触发但**缺值** | 关键指标无法核对 |
| 4 | 任一关键项 `✘` 且**无替代** | 原方案不可行 |
| 5 | 命中 **`severity: blocker`** 风险 | 可能造成安全事故 |
| 6 | 涉及**安规 / 认证 / 隔离 / 保险丝**的替代 | 认证失效 |
| 7 | **定时/时钟基准**或**固件绑定器件**的替代 | 功能不兼容 |
| 8 | 发现**已 EOL / LTB** 且剩余需求不明 | 无法定 LTB 数量 |
| 9 | 报价单出现**红色行**（无法匹配） | 官方要求人工干预 |
| 10 | 整单 ≥500 元且需 1688 阶梯价 | **阶梯价自动化取不到**，必须人工询盘 |
| 11 | 淘宝/1688 结果**空白** | 登录态过期，需人工扫码 |
| 12 | 用户要求的渠道组合**平台不支持**（如「公共库存 + Consign」） | 下单会失败 |

**第 6/7 条特别说明**：这三类器件（安全件、定时件、固件绑定件）**参数一样也不等于可替换**。看到「参数全 ✔ 所以可以替」的想法要立刻打住。

## 15 知识库索引

### 15.1 数据模型：part vs supplier-item

**这是全篇最重要的模型**（来自 InvenTree 的验证）：

- **part** = 器件的抽象（`STM32F103C8T6`，带参数集），对应 `data/spec-rules.yaml` 的 `critical[].key`
- **supplier-item** = 某个渠道对某个 part 的具体报价与库存（`C8734 @ 立创 ¥3.38@1000` / `STM32F103C8T6 @ 淘宝 ¥1.02`），对应 `lcsc.py` / `taobao.py` / `distributor.py` 各自的返回

**禁止拿 A 渠道的价格去比 B 渠道的库存。** 比价只能在**同规格**（同 part）的 supplier-item 之间做。

### 15.2 知识库文件

| 文件 | 内容 | 谁在用 |
|---|---|---|
| `data/categories.yaml` | 25 个 family、`catalog_id`、关键词、必填参数 | `pick.py` |
| `data/spec-rules.yaml` | 32 个 family 的 `critical` / `conditional_critical` / `substitute_equivalence` | `spec.py` |
| `data/knowledge/channels.yaml` | 8 类渠道的**接入方式 / 商业条款 / 能力边界 / 适用场景** | 人 + agent |
| `data/knowledge/risk-checklist.yaml` | 风险清单（现象 / 判据 / 检测命令 / 规避动作 / 严重度） | 人 + agent |

## 16 边界与已知限制

> **这一段不是免责声明，是使用说明书。** 说「不知道」比编一个数安全。

| 限制 | 影响 | 应对 |
|---|---|---|
| **立创参数区间筛选无服务端支持** | `queryParameterValue` 返 0 条 | 只能本地过滤 |
| **立创 `pageSize > 30` 静默返 0** | 大 `--limit` 会误判无货 | 分页或减 limit |
| **立创多值分隔符是 `$` 不是逗号** | 多值查询写错就查不到 | 按 `$` 拼 |
| **1688 阶梯价取不到** | 「走量更便宜」无法用数据证实 | 标「阶梯价未验证」+ 人工询盘 |
| **京东销量排序参数未知** | 京东只能做价格锚 | 不做销量排序 |
| **淘宝翻页未自动化** | 只覆盖当前页 | 结果里注明页数 |
| **淘宝登录态会过期** | 长期运行的主要单点故障 | 空白即判「需登录」，不重试 |
| **验证码/滑块阈值未知** | 一旦出现必须人工过 | 不要在自动流程里硬刚 |
| **价格是瞬时快照** | 比价结论只在采集时刻有效 | 落盘带时间戳 |
| **SKU 规格与型号映射不可靠** | 一条链接覆盖多个规格 | 按 SKU 名文本匹配，标注错配风险 |
| **立创商城 ≠ 嘉立创 SMT** | 两套库存/价格系统 | 商城料**不能随 PCB 寄** |
| **不支持的渠道组合** | 公共库存 + Consign 不行 | 按官方组合拆分 |

**遇到表外的情况**：先查 `research/methodology-survey.md` 的来源清单，再查本文 §12。**仍然无解 → 问人。**

## 附：主动核对清单（对应 `pick.py --verify N`）

选型输出之后，**必须**回到数据源做一次主动核对，而不是把候选清单直接当结论。
接口能核的、必须核的、只能人工的，分三类：

| 类别 | 项目 | 手段 | 不过关怎么办 |
|---|---|---|---|
| 接口能核 | 库存是否 ≥ 采购量 | `pick.py --verify` 重取 `stock` | 分批 / 换料 / 走 1688 询盘 |
| 接口能核 | 阶梯价是否变动 | 重算 `price_at(qty)` | 价格快照过期，重出报价 |
| 接口能核 | 是否停售/停产 | 商品名含"停售""停产" | 转 `lcsc.py alternate <C号>` |
| 接口能核 | 有没有数据手册 | `datasheet_pdf()` | 无手册 → 找原厂/分销商页确认规格 |
| 接口能核 | 功能类型是否对 | `function_check()` 正/反向词 | `mismatch` 直接剔除；`unknown` 查手册 |
| 接口能核 | 封装与面积 | `pkg_meta()` / `pkg_relation()` | 面积差 >10% 或引脚数不同 → 人工确认 |
| 只能人工 | 绝对最大额定值 | 手册 §Absolute Maximum Ratings | 超一点都不可接受 |
| 只能人工 | 焊盘图 / 钢网开口 | 手册 §Package Outline | 封装不符时必看 |
| 只能人工 | EOL / PCN / 批次变更 | 原厂站公告、代理通知 | 有 PCN 必须重新验证 |
| 只能人工 | 渠道真伪 | 原厂 1ku 价 vs 报价（差太多=散新/翻新） | 走 `origin.py` / `distributor.py` 比 |

**判据**：只要有任何一项落在"只能人工"且还没有人工结论，选型结论的措辞就必须是
「候选 + 待确认项」，不能写成「已确认可用」。
