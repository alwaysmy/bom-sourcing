## 0. 一页结论

选 MOSFET 的真正难点不是"参数多"，而是**参数分布在两个互不相通的平面**：

| 平面 | 内容 | 立创可得性 | 自动化等级 |
| --- | --- | --- | --- |
| **选型平面** | Vdss、Id、RDS(on)@Vgs、沟道类型、封装、价格、库存 | 4 个键 100% 覆盖 | **A：可自动判定并可自动排序** |
| **校核平面** | Pd@Tc、Rθja、Vgs(th)、Vgs(max)、Qg、Ciss、Qrr、trr、EAS、EAR、SOA、工艺、Tjmax | 几乎 0% 覆盖 | **C：必须查手册，机器只能生成待办** |

**立创能自动判的（4 项 + 2 项半自动）**

1. `Vdss` 耐压 —— 100% 覆盖、99.7% 可解析。
2. `Id` 连续漏极电流 —— 100% 覆盖、93.6% 可解析（mA 与双值需处理）。
3. `RDS(on)` 导通电阻 —— 100% 覆盖、100% 可解析，但**必须带 `@Vgs` 条件比较**。
4. 沟道类型（藏在 `数量` 键里，如 `1个N沟道`）—— 99% 覆盖。
5. 封装 —— 99.4% 非空，但**写法不归一**（`SOT-23`/`SOT23` 等 49 种写法），需 1 张映射表。
6. 价格/库存/销量 —— 100%，可直接做"同规格最便宜"排序。

**立创不能自动判的（必须查手册，机器不能给"通过"结论）**

`Pd@Tc=25℃`（0.7%）、`Vgs(th)`（0.3%）、`Vgs(max)`、`Qg`、`Ciss`、`Coss`、`Qrr`、体二极管 `trr`、
`Rθja`/`Rθjc`、`Tjmax`、`EAS`/`EAR`、`SOA` 曲线、**工艺类型**、`AEC-Q101` 认证状态、EOL 状态。

**为什么 SOA 必须查手册**（详见 §4.1）：SOA 图是**实测**出来的，不是从任何参数算出来的
（Nexperia 明确说明其 SOA 特性为 measured 而非 calculated，Spirito 能力限直接画在 SOA 图上）；
且 SOA 图的成立前提包含芯片单元一致性、die attach 焊层完整性（无空洞/无倾斜）、热阻分布均匀 ——
这三条**没有任何一个立创字段能反映**。更关键的是：功率 MOSFET 在线性区低于零温度系数点（ZTC）时
`∂I_D/∂T > 0`，局部热点会**正反馈**，用"算平均结温"的方法判安全在物理上就是错的。

## 1. 立创数据面的真实形状（实测）

### 1.1 检索 API 的服务端能力：只有 6 个杠杆

`lcsc.py raw_search` 最终只往 `POST` 体里塞这些字段（`scripts/lcsc.py:256-276`）：

| 字段 | 语义 | 实测结论 |
| --- | --- | --- |
| `keyword` | 自由文本 | **数字 token 会被当参数做「精确等于」匹配**，见 §1.1.1 |
| `catalogIdFilter` | 类目 ID | MOSFET = `381`（`场效应管(MOSFET)`） |
| `brandIdFilter` | 品牌 ID | 可用，需先取 `brands[]` |
| `standardFilter` | 封装 | **精确匹配**，写法必须与商城一致 |
| `startPrice`/`endPrice` | 单价区间 | 可用 |
| `sortNumber` | 排序 | `0` 综合 / `1` 单价升 / `2` 单价降 / `3` 库存升 / `4` 库存降 / `6` 销量降 |
| `spotFilter` | 现货 | **只认 `1`**；传 `0` 静默返回 0 条（`lcsc.py:259` 已注释） |

#### 1.1.1 关键词里的数字 = 精确等于，不是 ≥

`probe/mosfet/verify_semantics.py` + `probe_paging.py` 实测：

| 关键词 | 返回 30 条的 Vdss 分布 | 返回 30 条的 Id 分布 | 结论 |
| --- | --- | --- | --- |
| `N沟道 30V 5A` | `30V` × 30 | `5A` × 30 | 双数字 → 双精确过滤 |
| `N沟道 30V 6A` | `30V` × 30 | `6A` × 30 | 同上 |
| `N沟道 30V 8A` | `30V` × 30 | `8A` × 30 | 同上 |
| `N沟道 30V` | `30V` × 29 + `30V；30V` × 1 | `5.8A`×6、`100mA`×4、`10A`×2、`60A`… | 只给电压 → 电流全放行 |
| `N沟道 55V` | `55V` × 30 | — | 55V 是真实档位，纯精确 |
| `N沟道 35V` | `35V`×13 + `60V`×7 + `30V`×2 + `200V`×2 | — | **35V 档位料少 → 自动降级为模糊 OR** |
| `N沟道 33V` | `33V`×17 + `60V`×3 + `100V`×3 + `1.2kV`×3 | — | 同上 |

**三个必须写进实现的事实：**

1. **`≥` 无法表达**。`30V 5A` 只返回 Id **恰好 5A** 的料；`AO3400A`（30V/5.7A）**不会**出现在结果里。
   → 需求 `Id ≥ 5A` 必须写成「电压精确 + 客户端 `>=` 过滤」，或者用 `30V` 取全档再筛。
2. **精确档位不存在时会静默降级为模糊**，返回前一两条好的、后面全是噪声。
   → 结果集必须**逐条校验 Vdss 是否等于查询值**，否则会把 60V/200V 的料当 35V 用。
3. **参数值会被包 HTML 高亮标签**：命中关键词的参数值返回
   `<SPAN CLASS='LUCENE_HIGHLIGHT_CLASS'>30V</SPAN>`。
   `lcsc.py:619` 的 `normalize()` 里 `strip_html()` 已经处理掉了，所以走 `raw_search` 看不到；
   **但任何直接调 `_post` 的新代码必须先 `strip_html`**，否则数值解析全灭。

#### 1.1.2 `totalCount` 有 1500 硬上限

`probe/mosfet/probe_total_cap.py`：

| 查询 | `totalCount` | `countPage` | 第 51 页 | 判定 |
| --- | --- | --- | --- | --- |
| 类目全部 `场效应管(MOSFET)` | **1500** | **50** | 空 | 饱和 |
| `TO-247` | **1500** | **50** | — | 饱和 |

#### 1.1.3 不存在服务端参数范围筛选

### 1.3 值格式陷阱（解析器必须处理）

| 陷阱 | 实例（真实记录） | 频次 | 处理方式 |
| --- | --- | --- | --- |
| 电流用 mA | `2N7002` → `115mA`、`2N7002KCQ` → `300mA` | 21/330 条 Id | 单位换算，`mA → A` |
| 电流双值（双芯片） | `FDPC5018SG` → `32A；17A`、`LWD3008ADC` → `45A；35A` | 2 条 | 取**较大值**并标记 `dual_die` |
| 电压带 kV | `STH3N150-2` → `1.5kV` | 1 条（全体唯一失败） | `kV → V` |
| 电压双值 | `30V；30V`（同一料两行 Vdss） | 1 条 | 取较大值 |
| 电阻单位 mΩ / Ω | `48mΩ` 282 条 / `5Ω` 18 条 | — | **必须换算到 Ω 再比** |
| 电阻多条件 | `AO3401A` → `47mΩ@10V；85mΩ@2.5V；60mΩ@4.5V` | 28/330 条有 ≥2 个 `@` | 按目标 Vgs 插值/取最接近档 |
| 电阻带测试电流 | `10V,3A` | 2 条 | 逗号后是 ID，不是 Vgs |
| `数量` 为空 | `""` | 3 条 | 判为未知沟道，**不得默认 N** |
| `数量` 复合 | `1个N沟道+1个P沟道` | 1 条 | 标记 `complementary` |
| **极性恒为正** | P 沟道料 Vdss 也是 `30V`（不是 `-30V`）、Id 也是 `4.2A` | 330/330 | **禁止用符号判极性**，必须靠 `数量` 键 |

## 2. 判据 A：六维可判定判据

每一维给：**物理含义 / 单位 / 典型判据 / 如何从立创取 / 取不到怎么办 / 自动化等级**。

自动化等级定义：

| 等级 | 含义 | 机器可否给结论 |
| --- | --- | --- |
| **A** | 立创有字段且有值，可解析 | 可自动判定 + 可自动排序 |
| **B** | 立创无字段，但可从 `name`/型号/品牌推断 | 可给"疑似"，**不可单独作为结论** |
| **C** | 立创完全无信息 | **只能生成待办**，禁止输出"通过" |
| **D** | 需要物理计算（用 A 类数据算） | 可自动算，但结果依赖假设 |

### 2.1 电气维度

**E1 的降额为什么是 1.5×/2×**：Vdss 本身有正温度系数（约 +0.1%/℃），热了反而更耐压；
真正吃掉余量的是**关断尖峰** `V_spike = V_rail + L_stray×di/dt`。感性负载断流时能量全部由雪崩吸收，
所以"感性 → 2×"不是保守，是**雪崩能量预算**（见 §2.3）。

**E3 的 `@Vgs` 条件为什么不能跨**：实测 `AO3401A` 一个料就同时给出
`47mΩ@10V；85mΩ@2.5V；60mΩ@4.5V` —— **同一颗管子差 1.8 倍**。
而 `AO3400A` 是 `48mΩ@2.5V`、`AO3400`（GOODWORK）是 `28mΩ@10V`，数值上后者"更好"，
但 3.3V 驱动下 `AO3400A` 的实际表现可能反而更好。**跨 `@Vgs` 直接比大小是选型里最高频的错误**。

**E3 的温度折算**（D 级，需要假设）：
```
R_DS(on)(Tj) = R_DS(on)(25℃) × (1 + α×(Tj − 25))
α ≈ 0.004 ~ 0.006 /℃   （硅功率 MOSFET 典型值，必须用 datasheet 的
                          "Normalized RDS(on) vs Tj" 曲线校准）
Tj = 125℃ → ×1.4 ~ 1.6      Tj = 150℃ → ×1.5 ~ 1.75
```
低圧沟槽管（30V 级）实测常达 **×1.8 @125℃**，高圧超结管约 ×1.4。**取 1.5 是中性默认，不是最优**。

**`Pd@Tc=25℃` 与 `Pd@Ta=25℃` 的区别（必须写进规则）**：

```
Pd@Tc=25℃  →  壳温被强制维持在 25℃  →  只反映 Rθjc
Pd@Ta=25℃  →  环境 25℃、无散热器      →  反映 Rθja（含 PCB）

同一颗管子，SOT-23 封装：
  Pd@Tc=25℃ ≈ 1.0 ~ 1.4 W      （Rθjc ≈ 90 K/W）
  Pd@Ta=25℃ ≈ 0.3 ~ 0.5 W      （Rθja ≈ 250 ~ 350 K/W）
差 3 倍以上。拿 Pd@Tc 当"能耗散的功率"是选型里第二个高频错误。
```

**热阻串联（D 级，可自动算）**：
```
Tj = Ta + P × (Rθja)                       # 无散热器
Tj = Ta + P × (Rθjc + Rθcs + Rθsa)         # 有散热器
Rθcs ≈ 0.5 ~ 1.5 K/W  （导热硅脂/绝缘片；云母片 +2~3 K/W）
Rθsa = 散热器规格（自然对流 vs 强制风冷差 3~10 倍）
```

### 2.4 工艺类型维度

#### 四种主流工艺的物理对比

| 工艺 | 英文 | 结构特征 | `R_DS(on)×Q_g` 折中 | 抗雪崩能力 | 线性区 SOA | 典型电压段 | 立创可判 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **平面** | Planar | 栅极在表面，电流横向再纵向 | 差（`R_DS(on)` 大） | **最强**（寄生 BJT 增益低，易做 UIS） | **最好**（单元一致性高，无热点集中） | 高压 ≥ 200V | **不可判**（name 0 次） |
| **沟槽** | Trench | 栅极刻进硅里，沟道垂直 | 好（单元密度高） | 中（寄生 BJT 易触发） | 中 | 30 ~ 200V | **部分**（name 17 次） |

## 4. SOA / 能量校核最小可行算法（C 部分）

### 4.1 为什么 SOA 必须查手册（不是"偷懒"，是物理）

**理由 1：SOA 是实测曲线，不是参数计算出来的。**
Nexperia 明确说明（Arrow 技术问答）：2010 年之后其全部 MOSFET 的 SOA 特性为 **measured**，
线性模式能力的边界直接画在 SOA 图上；Spirito 能力限也是**标示**在 SOA 图上，而不是从 `R_DS(on)` 算的。
→ 立创没有 SOA 字段，任何"算出来的 SOA"都是伪造。

**理由 2：线性区存在正反馈，平均结温判据在物理上失效。**
功率 MOSFET 在线性区（`V_GS` 接近 `V_th`、`I_D` 由 `V_GS` 决定）工作在**零温度系数点（ZTC）以下**，
此处 `∂I_D/∂T > 0`：局部热点 → 该处电流更大 → 更热 → 正反馈。
Spirito（2005）给出的稳定性判据是

```
V_DS · ∂I_D/∂T  ≤  1 / f_th        （f_th = 热反馈系数）
```

这个判据**用不到**"平均结温是否超限"，它要求的是器件内部**热分布均匀**。
所以"算出 Tj = 140℃ < 150℃ 所以安全"是**错误的推理**。

**理由 3：SOA 图的成立前提是三条工艺条件，立创一条都看不到。**
① 芯片单元（cell）一致性；② die attach 焊层完整性（无空洞、无倾斜）；
③ 热阻分布均匀。这三条**只能**由 datasheet + 厂商质量体系保证。

**结论**：SOA / `E_AS` / `Zth` 三项**没有 datasheet 就不能给结论**。
算法能做的只有：把"需要查什么、查回来怎么代公式"这件事自动化。

### 4.2 输入 / 输出定义

**输入**

| 名称 | 符号 | 单位 | 来源 | 必需 |
| --- | --- | --- | --- | --- |
| 母线电压 | `V_DD` | V | 电路 | ✅ |
| 负载电感 | `L` | H | 电机绕组/继电器线圈/线缆 | ✅ |
| 稳态/峰值电流 | `I` | A | 负载 | ✅ |
| 开关频率 | `f_sw` | Hz | 驱动 | 开关场景 ✅ |
| 占空比 | `D` | — | 驱动 | 开关场景 ✅ |
| 开通/关断时间 | `t_r`/`t_f` | s | 驱动 + `Q_g` | 开关场景 |
| 环境温度 | `T_a` | ℃ | 环境 | ✅ |
| 散热条件 | `Rθ_sa` | K/W | 散热器 | 可选 |
| 器件参数 | `V_DSS`,`R_DS(on)@Vgs`,`Rθjc`,`Tjmax`,`E_AS`,`SOA` | — | **datasheet** | 视场景 |

**输出**

| 名称 | 单位 | 说明 |
| --- | --- | --- |
| `verdict` | enum | `PASS` / `FAIL` / `NEED_DATASHEET` / `NEED_THERMAL_MODEL` |
| `Tj_est` | ℃ | 估算结温（含假设标注） |
| `EAS_required` | mJ | 需要的雪崩能量 |
| `EAS_margin` | 倍 | `E_AS(器件) / EAS_required` |
| `soa_point` | `(V_DS, I_D, t_pulse)` | 需在 SOA 上核对的点 |
| `missing` | `string[]` | 缺哪些 datasheet 参数 |

### 4.3 算法（伪代码）

```text
FUNCTION check_mosfet(intent, part) -> Report

  # ── 段 0：判据可用性门（先判"能不能判"）────────────────────
  missing = []
  FOR key IN [V_DSS, R_DS_on, Rθjc, Tjmax, E_AS, SOA]:
      IF part.datasheet.get(key) == NULL:
          missing.append(key)

  # ── 段 1：稳态通态损耗 + 结温（D 级，可算）───────────────
  R25   = part.R_DS_on_at(intent.Vgs)              # 必须带 @Vgs 条件
  Tj    = intent.Ta + 40                            # 初值猜测
  REPEAT 5 TIMES:                                   # 迭代收敛（Rds 随温升）
      R_hot = R25 * (1 + ALPHA * (Tj - 25))         # ALPHA ≈ 0.0045/℃
      P_cond = intent.I^2 * R_hot * intent.D
      P_sw   = 0.5 * intent.V_DD * intent.I * (intent.t_r + intent.t_f) * intent.f_sw
      P_tot  = P_cond + P_sw
      R_th   = part.Rθjc + (intent.Rθ_sa ?? 0) + 1.0     # 1.0 = Rθcs 默认
      Tj_new = intent.Ta + P_tot * R_th
      IF |Tj_new - Tj| < 0.5: BREAK
      Tj = Tj_new
  IF Tj > 0.8 * part.Tjmax:  verdict = FAIL  # 80% 降额
  IF Rθjc IN missing:        verdict = NEED_THERMAL_MODEL

  # ── 段 2：单脉冲雪崩能量（C 级，必须查手册）──────────────
  # 依据：Infineon "Some key facts about avalanche" 式(1)
  #       IEC 60747-8:2010+AMD1:2021 §6.2.3.2 / Fig.16 / Fig.18
  #       JEDEC JESD24-5 (UIS)
  V_AV   = part.V_AV_DSS ?? (1.2 * part.V_DSS)      # 无实测值时取 1.2×V_DSS 作估算
  EAS_req = 0.5 * intent.L * intent.I^2 * V_AV / (V_AV - intent.V_DD)
  #   若雪崩期间 VDD 被断开（低边斩波/继电器断开）：
  #       EAS_req = 0.5 * intent.L * intent.I^2
  t_av    = intent.L * intent.I / (V_AV - intent.V_DD)     # 雪崩持续时间
  IF part.E_AS == NULL:
      missing.append("E_AS");  verdict = NEED_DATASHEET
  ELSE:
      margin = part.E_AS / EAS_req
      IF margin < 2.0: verdict = FAIL          # 余量 ≥ 2×
      # 交叉校核：用瞬态热阻抗复核（Zth 曲线）
      IF part.Z_th != NULL:
          ΔTj = EAS_req * part.Z_th(t_av) / t_av
          IF Tj + ΔTj > part.Tjmax: verdict = FAIL

  # ── 段 3：SOA 逐点核对（C 级，必须查手册）────────────────
  # 需要核对的点：开通瞬态 (V_DD, I_inrush, t_start)
  #              关断瞬态 (V_spike, I_load, t_f)
  FOR pt IN [(intent.V_DD, intent.I_inrush, intent.t_start),
             (intent.V_spike, intent.I_load, intent.t_f)]:
      IF part.SOA == NULL:
          missing.append("SOA");  verdict = NEED_DATASHEET
      ELSE IF NOT inside_soa(pt):  verdict = FAIL
      #   inside_soa 用 1.5× 余量：点必须落在 (V/1.5, I/1.5) 内

  # ── 段 4：线性区额外门（Spirito）─────────────────────────
  IF intent.mode == LINEAR:
      # 只要 datasheet 没给 SOA，一律不可放行
      IF part.SOA == NULL OR part.process == UNKNOWN:
          verdict = NEED_DATASHEET
      # 即使有 SOA，也要确认是"实测"而非"计算"
      #   判据：SOA 图在低 VDS 段是否平直（计算值会平直，实测值有 Spirito 折线）

  RETURN {verdict, Tj_est: Tj, EAS_required, EAS_margin: margin,
          soa_point, missing}
```

**`E_AS` 算例（Infineon 原文数值，用于自检）**：
```
L = 100 µH, i_AS(0) = 50 A, V_DS,peak = 60 V × 1.2 = 72 V, V_DD = 12 V

不带降额（VDD 断开）：EAS1 = ½ × 100µH × 50² = 125 mJ

```
→ 实现里必须**明确 `V_DD` 是否在雪崩期间被断开**，两个结果差 20%。

### 4.5 算法能/不能给的结论（诚实边界）

| 场景 | 算法输出 | 可以给"通过"吗 |
| --- | --- | --- |
| 通态损耗 + 结温 | `Tj_est` + 假设清单 | **可以**（有 `Rθjc`+`Tjmax` 时，D 级） |
| 单脉冲雪崩 | `EAS_required` + `margin` | **不可以**（`E_AS` 必须查手册） |
| 线性区 / 缓启动 / 热插拔 | `soa_point` + `missing[]` | **绝对不可以** |
| 开关损耗 | `P_sw` 估算 | **可以**，但需 `Q_g`（C 级，缺省时标注假设） |
| 浪涌 | — | **不可以**（无 `I_surge` 额定，只能靠 SOA） |

| **期望** | ① 给出候选（`Vdss ≥ 60`、`Id ≥ 3`、N 沟道）；② 计算 `EAS_required`；③ **明确输出 `NEED_DATASHEET`** 并列出缺 `E_AS` |

| **通过标准** | ① `EAS_required ≈ 600 mJ ±1%`；② `verdict == NEED_DATASHEET`；③ `missing` 含 `E_AS`；④ **禁止**出现"通过/可用"字样；⑤ 若某料 `name` 含 `UIS`，只能标为"线索 B 级"，**不得**升格为结论 |
| **expect_guard** | 必须提示 `V_DD` 是否在雪崩中断开（差 20%）；必须提示 `E_AS` 的测试 `I_D` 条件不可比 |
| **当前是否通过** | ❌ **不通过**（`pick.py` 无 `E_AS` 概念，会直接给"命中 N 条"结论） |

### 用例 3 —— 缓启动 / inrush（负向，必须拒绝给结论）

| 项 | 内容 |
| --- | --- |
| **意图** | `找 24V 输入、带 10A 浪涌、软启动 10ms 的负载开关 MOS` |
| **期望** | ① 候选 `Vdss ≥ 1.5×24 = 36V`（建议 48V 档）；② `I_D ≥ 10A`；③ 输出 `soa_point = (24V, 10A, 10ms)` 并要求核 SOA |

## 6. 已定位缺陷（P0 级，均有复现）

### P0-1 单字母子串匹配 → 品类解析全错

```
$ python pick.py "找 30V 5A 的 N 沟道 MOS" --qty 100
品类: 功率电感（catalogIdFilter=544，关键词=功率电感）
$ python pick.py "找 -30V 5A 的 P 沟道 MOS" --qty 100
品类: 单片机(MCU/MPU/SOC)（catalogIdFilter=11329，关键词=单片机(MCU/MPU/SOC)）
  1  C8734  STM32F103C8T6  ST(意法半导体)  LQFP-48(7x7)  ... 7.07
```

**根因**：`pick.py:236 match_family(token, cats)` 用 `n.lower() in low or low in n.lower()` 做**子串**匹配。
单字母 `"N"` → `"n" in "inductor"` 为真 → 命中 `inductor`；`"P"` → `"p" in "mpu"` 为真 → 命中 `mpu`。

**修复**：单字母 / 短 token（`len(token) < 3`）禁止参与子串匹配，只允许**精确别名**命中；
或先按 `沟道`/`MOS`/`MOSFET` 关键词短路到 `mosfet` family。

### P0-2 负号丢失 + 极性约束缺失

**根因 A**：`pick.py:335 parse_intent` 的电压正则
`r"(\d+(?:\.\d+)?)\s*(?:~\s*(\d+(?:\.\d+)?))?\s*V\b"` **没有前导 `[-−]?`**，
`-30V` 被解析成 `30V`（数值对，语义错）。

**根因 B**：`polarity` 别名是 `["极性","输出极性","类型"]`，
而 MOSFET 的沟道在立创里存在 **`数量`** 键（`1个N沟道`），
`count_type → ["数量"]` 被当成"通道数"（text 比较），**P/N 沟道从未生成 `count_type` 约束**。

**修复**：
```python
# 电压
r"([-−]?)\s*(\d+(?:\.\d+)?)\s*(?:~\s*([-−]?\d+(?:\.\d+)?))?\s*V\b"
# 负号 → polarity = "P"，取 abs 值
# 沟道关键词 N/P → count_type 约束 "N沟道" / "P沟道"（子串包含）
```

### P0-3 单位缩放 1000× 错误（最严重，会买错料）

```
$ python -c "import spec; print(spec.parse_ohm('48mΩ'), spec.parse_ohm('10mΩ'), spec.parse_ohm('1mΩ'))"
48.0 10.0 1.0            # 应为 0.048  0.01  0.001
$ python -c "import spec; print(spec.to_num('48m'))"
0.048                    # to_num 是对的
```

**根因**：`spec.py:117 parse_ohm` 的正则单位类 `([kKMGRr]?)` **漏掉 `m` / `µ` / `u` / `n` / `p`**。

**后果实测**（`pick_i5_lowrds_20261106_174432.txt`）：
`RDS<=10mΩ` 返回 `2N7002`(5Ω)、`2N7002,215`(5Ω)、`BSS138`(1.1Ω)、`BSS138LT1G`(5.6Ω)、`2SK3018`(8Ω)
—— **全部超规格 100~800 倍**。

**修复**：
```python
_MULT = {"p": 1e-12, "n": 1e-9, "u": 1e-6, "µ": 1e-6, "m": 1e-3,
         "": 1.0, "k": 1e3, "K": 1e3, "M": 1e6, "G": 1e9, "R": 1.0, "r": 1.0}
```
（`R`/`r` 是欧姆的德式写法，如 `4R7` = 4.7Ω，保留。）

### P0-4 关键词数字被当精确等于 → 假阴性

**实测**（§1.1.1）：`N沟道 30V 5A` 只返回 `Id` **恰好 5A** 的料，
`AO3400A`（5.7A，最常用的 30V 料）**被排除**。

**修复**：
1. **电压** 用精确（`30V` 是真实档位，且 `≥` 语义由客户端做）；
2. **电流不要**塞进关键词 —— 用 `Vdss` 拿全档再客户端 `Id >=` 过滤；
3. 结果集**逐条校验** `Vdss == 查询值`，剔除模糊降级带来的噪声（`35V` 查询里的 `60V/200V` 料）；
4. 任何直接调 `_post` 的代码必须先 `strip_html`（参数值带 `<SPAN CLASS='LUCENE_HIGHLIGHT_CLASS'>`）。

### P0-5（新）`totalCount` 1500 上限 → 无法判断"命中多少"

`= 1500` 只表示"≥1500"。做"市场有没有"的判断必须用 `< 1500` 的窄查询，
或按 `Vdss` 切片枚举（每片 < 1500）。
